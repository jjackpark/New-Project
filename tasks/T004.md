## 작업 노트

_(진행하면서 결정사항, 이슈, 리뷰 코멘트를 이 아래에 기록)_

- 2026-09-17: 백엔드(서버 API)가 아직 없는 단계라, 사용자 지시로 세션 인증을 서버 라운드트립 없이 **브라우저(localStorage) 기준으로 간소화**해서 구현했다 — "공용 PC 한 대"를 서버로 보는 현재 배포 전제와 맞고, 나중에 실제 서버가 생기면 `App.auth.login/logout/currentUser`(web/app-auth.js) 내부만 fetch 기반으로 교체하면 되도록 인터페이스를 분리해뒀다.
  - `web/app-auth.js`: `App.store`의 `users`(username/password/role)와 대조해 로그인, 성공 시 `sm_session_v1` localStorage 키에 세션 저장. 로그아웃은 키 삭제.
  - `web/app.js`: 로그인 전이면 `#login-root` 카드 화면만 보여주고 사이드바/탭(`#app-layout`)은 숨김. 로그인 성공/로그아웃 시 화면 토글.
  - `web/views/settings.js`: 사용자 계정 관리(관리자 전용) 폼에 비밀번호 필드 추가(수정 시 비워두면 기존 비밀번호 유지).
  - 비밀번호는 평문으로 저장된다(해싱 없음) — 사내 단일 PC 대상의 임시 구현이라는 전제 하의 의도적 간소화이며, 실제 서버 붙일 때 해싱을 추가해야 한다.
  - adversarial-reviewer subagent는 이번 세션에서 사용자가 "서브에이전트 사용 중지"를 지시해 호출하지 않았다 — 대신 `npm run lint`, `npm run build` 통과 확인 + Claude in Chrome으로 로그인 성공/실패/로그아웃/권한별 화면 분기를 직접 브라우저에서 검증했다.
